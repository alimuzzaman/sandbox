# L1.2 audit-only tooling

L1.2 adds a small, unregistered Python package at
`tools/audit_agent_usage/`. It is a local file-to-file boundary for the
synthetic `audit-fixture-v1` JSONL fixture. It does not import Sandbox modules
or inspect a corpus, runtime, remote host, browser store, database, or opaque
store.

## Contract

The parser accepts two explicit paths:

```text
python3 -m tools.audit_agent_usage \
  --input docs/audits/2026-08-24-sandbox-agent-tool-audit/fixtures/synthetic-events.jsonl \
  --output-dir /tmp/audit-agent-usage-output
```

The output directory contains `normalized.jsonl`, `exclusions.jsonl`, and
`accounting.json`. A caller may instead use the pure API:

```python
from tools.audit_agent_usage import parse_to_directory, validate_output_files

parse_to_directory(input_path, output_dir)
result = validate_output_files(
    output_dir / "normalized.jsonl",
    output_dir / "exclusions.jsonl",
    output_dir / "accounting.json",
)
assert result.ok
```

The versioned contracts are declared in `schema.py`:

- `audit-fixture-v1` is the accepted input shape;
- `audit-normalized-v1` is the emitted-row and exclusion-row shape;
- `audit-accounting-v1` is the terminal-count manifest.

Each physical input line receives exactly one terminal state: `malformed`,
`duplicate`, `excluded`, or `emitted`. Normalized rows retain the physical
`line_index`, explicit `event_index`, and `ordering_basis: file_order`.
Timestamps are an uncertainty annotation only: missing values stay missing and
backward values are marked `inversion`; no global timestamp sort is performed.

Transport delivery, tool invocation, command receipt, and task outcome are
four independent fields. A successful command or completed tool call never
upgrades an unknown or ambiguous task outcome.

Parent/child candidate signals retain their signal class, but
`relation_state` remains `unknown` and only the bounded `relation_join` class
is kept. Missing join identifiers never create a relation.

## Projection and safety boundary

The parser uses an allowlist of argument markers (`target_class`, `format`, a
cursor-presence marker, and closed label states). Headers and metadata are
represented only by `redacted`; nested values are not copied to derived rows.
Label keys are limited to `equals`, `plus`, `minus`, and `at`, and their values
are reduced to `present` or `formula_candidate`; prose, email-like text, and
formula bodies never enter derived output. Unknown input keys are ignored.

The parser validates the complete in-memory `ParseResult` before creating the
output directory. Derived files are staged through sibling temporary files and
committed with atomic replacement; a failed replacement attempts to roll the
file set back to its prior state and retains any backup whose restore fails.

Synthetic references such as `SYN-*` are retained for fixture traceability.
Other source references are hashed with the approved audit domain and emitted
as a short `SAFE-SRC-*` value. No reverse map is written. Basenames are
projected without emitting an absolute input path.

## Checks

Run the focused tests twice from the repository root:

```text
python3 -m unittest discover -s tests/audit_agent_usage -p 'test_*.py' -v
python3 -m unittest discover -s tests/audit_agent_usage -p 'test_*.py' -v
```

The test suite compares every synthetic normalized and exclusion row with the
accepted L1.1 expectation, checks all four terminal accounting identities,
exercises malformed/duplicate/unknown/partial/order/redaction/formula and
parent-child branches, validates stable references, and proves two output
directories are byte-identical. The validator also checks the terminal
partition and forbidden value classes without printing input values.

The audit-wide durable-field scan and whitespace check remain separate root
gates:

```text
docs/audits/2026-08-24-sandbox-agent-tool-audit/check-durable-artifacts.sh
git diff --check
```

This slice does not read or normalize any non-synthetic source and does not
generate a corpus, cohort, efficiency, backlog, or product report.
