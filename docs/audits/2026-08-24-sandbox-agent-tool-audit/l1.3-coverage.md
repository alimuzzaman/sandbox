# L1.3 coverage reconciler

L1.3 adds `tools/audit_agent_usage/coverage.py`, an unregistered,
file-to-file reconciler over the frozen synthetic fixture and the L1.2
`ParseResult`. It does not read an approved corpus, a transcript, an opaque
store, a credential source, a remote host, or a product runtime.

## Contract

Run the reconciler with an explicit input and output path:

```text
python3 -m tools.audit_agent_usage.coverage \
  --input docs/audits/2026-08-24-sandbox-agent-tool-audit/fixtures/synthetic-events.jsonl \
  --output-dir /tmp/audit-agent-coverage
```

The command writes `coverage-manifest.json`. The manifest is deterministic and
contains only safe fixture metadata, schema identifiers, bounded counts,
allowlisted status names, exclusion reasons, and the SHA-256 digest of the
explicit synthetic input. It never writes the input path or raw values.

Record accounting is explicit and disjoint:

```text
input_records = malformed + duplicate + excluded + emitted
parsed_records = duplicate + excluded + emitted
```

The manifest repeats these identities at the top level, per source, and in the
`units.record` object. Every exclusion row must have a bounded reason, and the
manifest reports the reason histogram plus a zero `without_reason` count.

## Unit boundaries

`units.file`, `units.record`, `units.session`, `units.event`, and
`units.command` are intentionally separate:

- `file` describes the one explicit fixture path and does not reuse record
  counters as a file count.
- `record` is the L1.2 physical-line accounting and is the only unit with the
  full malformed/duplicate/excluded/emitted terminal partition.
- `session` stays `unknown` when no session identifier is present. A safe
  source reference is never inferred to be a session join key.
- `event` counts emitted rows plus duplicate event exclusions. Malformed and
  non-event exclusions remain an explicit unknown-event count.
- `command` reports `command_exit_status` observations from emitted rows only.
  It does not claim that every tool event was a CLI command, and `unknown`,
  `failure`, and `timeout` remain distinct.

The four status layers (`transport_status`, `tool_call_status`,
`command_exit_status`, and `task_outcome`) are reported independently. Partial,
unavailable, blocked, unverified, ambiguous, and unknown states are not
upgraded or collapsed.

## Checks

The focused suite is run twice from the repository root:

```text
python3 -m unittest discover -s tests/audit_agent_usage -p 'test_*.py' -v
python3 -m unittest discover -s tests/audit_agent_usage -p 'test_*.py' -v
```

The tests assert the frozen fixture counts and exclusion reasons, compare two
manifest files byte-for-byte, check all unit boundaries and status layers, and
run the existing forbidden-value validator over the manifest. The audit-wide
durable-field scan and whitespace checks remain separate gates:

```text
docs/audits/2026-08-24-sandbox-agent-tool-audit/check-durable-artifacts.sh
git diff --check
```

This remains provisional L1.3 evidence for Sol High review; it does not
authorize corpus normalization, generated reports, or any Sandbox product
change.
