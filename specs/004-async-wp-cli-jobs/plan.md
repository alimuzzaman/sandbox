# Implementation Plan: Async / Background WP-CLI Jobs

**Branch**: `feat/agent-tooling-specs` | **Date**: 2026-06-22 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/004-async-wp-cli-jobs/spec.md`

## Summary

Add a background-execution mode to the WP-CLI surface: `wp_cli(async=true)` and
`./sb wp --async` start a command detached, returning a 16-hex `job_id` immediately;
`wp_cli_job` / `./sb job` poll incremental output + status; `wp_cli_job_kill` /
`./sb job --kill` cancel. State is file-based under each instance's bind-mounted
`.sb-jobs/` (log + status + self-reported pid). Works on Docker (detached
`compose exec -d`) and herd (host `nohup`). Auto-pruned by age.

## Technical Context

**Language/Version**: Python 3 (`sandbox/` package + `mcp/wp-server/`); POSIX sh for the launch wrappers.

**Primary Dependencies**: existing `wp_cli`/`_wpcli` host helpers, `_compose`, `_is_herd`, `_wp_root`, `_host_run`, `_herd_host_env` in `mcp/wp-server/tools/wp.py`; the instance registry; the per-instance bind-mount at `runtime/wp-<instance>/`.

**Storage**: per-job files under `runtime/wp-<instance>/.sb-jobs/job_<id>.{log,status,pid}`. No DB.

**Testing**: live-stack verification (constitution IV) — run a real long command async on a Docker and a herd instance, poll to completion, kill one.

**Target Platform**: macOS/Linux; Docker Desktop/Engine + Laravel Herd.

**Project Type**: host CLI/MCP extension (single-entry `sb` + `sandbox/` package + `mcp/wp-server/`).

**Performance Goals**: async start returns in <~2s; poll is O(slice) via byte offset.

**Constraints**: async is only an execution mode for `wp` (no widened command set); job_id strictly validated (`^[a-f0-9]{16}$`) before any path use; artifacts gitignored.

**Scale/Scope**: 1 new MCP tool pair (`wp_cli_job`, `wp_cli_job_kill`) + `wp_cli` async param; 1 `jobs` CLI module + `wp`/`job` extensions.
