# Research: Secret Profiles and Create-Only Manager Migration (069)

Evidence base: source inventory r1, create contract r1, uniqueness audit r3, API metadata/revoke r1 (scratch root `/Users/alim/Sites/git/.scratch/sandbox/secret-profiles/`), and repo reads of `sandbox/secrets/{authority,sources}.py`, `providers/{broker,worker,base,http}.py`, `config/secrets.py`. Labels: VERIFIED = read in source/docs; INFERRED = reasoned; UNPROVEN-LIVE = must be shown on the disposable instance before any real migration.

## R1 Where ownership config lives
- **Decision**: new optional key `secrets.ownership` (`profiles`, `entries`) accepted in exactly one layer (project or machine override); present in both layers → `ValueError("ownership configuration declared in both layers")`. Destinations are operator metadata; nothing hard-coded.
- **Rationale**: mirrors `sources`/`useProfiles` layering (config/secrets.py L333-380, VERIFIED); a single owner layer keeps the map reviewable as one unit and its digest stable.
- **Alternatives**: separate file (rejected: second config loader, CLAUDE.md table says per-project config lives in `sandbox.config.json`/`sandbox.local.yml`); per-entry layering (rejected: partial maps across layers make "complete map" binding ambiguous).

## R2 Map shape and fail-closed classes
- **Decision**: `entries` is a **list** (not a mapping) so a source entry assigned twice survives parsing and is reported `multiply_assigned`. Profile value `undecided` is reserved. Structural errors (unknown field, bad slug, bad env name, secret-like metadata via `_SECRET_LIKE_METADATA`) raise at normalization; ownership-decision problems never raise there, they are classification results that block migration.
- **Rationale**: FR-003/FR-004; YAML/JSON mappings silently collapse duplicate keys.

## R3 Authority digests without changing old fingerprints
- **Decision**: (a) new `ownership_digest(...)` with prefix `o1-` per (profile, capability) where capability ∈ {`read`,`create`}; payload covers version, canonical project root, profile name, domain, full destination descriptor, capability client id, sorted entries of that profile (source alias, key, name, consumer, origin) and, for `create`, the full sorted name list. (b) `_fingerprint` gains an optional `ownership_consumers` list for an infisical **source** consumed by ownership entries with `origin: source`; the key is added to the payload **only when non-empty**, so every existing `a1-` digest is byte-identical without ownership config (FR-051).
- **Rationale**: authority.py docstring L47-52 (VERIFIED): the digest is in the OS-credential lookup so a config change cannot reuse approved bootstrap material (hazard H1). New consumers of an existing credential must therefore force re-provisioning (`credential-set`).
- **Alternatives**: bumping `version` to 2 globally (rejected: changes every fingerprint).

## R4 Value-free destination existence (preflight)
- **Decision**: `GET /api/v4/secrets/{name}?projectId&environment&secretPath&type=shared&viewSecretValue=false&expandSecretReferences=false&includeImports=false`. Parse requires `secret.secretKey == name` and `secret.secretValueHidden is True`; any non-empty `secretValue` other than the provider's hidden placeholder is `response_invalid` (buffer wiped, run refuses). Not-found → `absent` only for HTTP 404 with a JSON error body; any other status → `unknown`, and any `unknown` refuses mutation (FR-012).
- **Evidence**: params and `secretValueHidden` field VERIFIED in docs and v4 route (api-metadata-revoke r1); what `secretValue` holds when hidden and the not-found status are **UNPROVEN-LIVE** (getSecretByNameRaw not read). Fail-closed parse makes the uncertainty safe; the disposable-instance proof must confirm 404 and the hidden placeholder, else mutation stays unavailable (`existence_unknown`).

## R5 Create contract
- **Decision**: `POST /api/v4/secrets/{name}` body exactly `{projectId, environment, secretPath, secretValue, secretComment, type:"shared"}`, `secretComment = "sandbox-ownership run=<run_id> controller=<controller_id>"` (non-secret, lets a second controller name the owner, FR-031). Classification: `{"secret":{...}}` with `secretKey==name`, `type=="shared"`, environment match, and (when present) `secretValue` byte-equal in RAM (`hmac.compare_digest`) → `created` (pending readback); `{"approval":{...}}` → `unresolved` + stop (FR-018); HTTP 400 whose message matches `^Secret '.+' already exists` → `conflict` + stop (FR-017); malformed/other → `acceptance_unknown` + stop (FR-028).
- **Evidence**: route/body VERIFIED (create-contract r1); duplicate → BadRequestError VERIFIED for V2 bridge; wire status 400 INFERRED; check-then-insert race is closed only by `uq_secrets_v2_key_folder_id_shared` (r3) and the 23505 mapping is UNVERIFIED → a unique-violation surfacing as 500 classifies as `acceptance_unknown`, reconciled on resume, never retried blindly.

## R6 Storage-contract admission
- **Decision**: mutation requires an operator-supplied evidence document (contracts/storage-evidence.md) carrying raw output of two fixed catalog queries run by the operator through their own DB process, bound to destination origin+projectId, captured ≤ 60 min before use, `expiresAt ≤ capturedAt+3600`, and reviewed inside the human approval (its SHA-256 is bound). Sandbox labels it **`operator_attested`** always; it never emits "verified"/"independently_verified" for storage. Admission parses the raw query output itself (index name `uq_secrets_v2_key_folder_id_shared`, table `secrets_v2`, normalized definition, `indisunique/indisvalid/indisready/indislive = t`) and rejects bare booleans, a version string, or source-only claims (FR-023/FR-024).
- **V2 selection predicate (source VERIFIED)**: v0.166.5 `shouldUseSecretV2Bridge(version)` is exactly `version === 3`. `project-bot-fns.ts:27-37` returns that flag for project.version 3 without a bot-key override; createSecretRaw calls getBotKey(projectId) without an override at secret-service.ts:1639. Q2 in storage-evidence.md binds the project ID without assuming its database type. Live execution remains UNPROVEN-LIVE. A source-cited non-empty `V2_SELECTION_QUERY` is mandatory before provider implementation completes (T024). A placeholder must not ship; unconfirmed capability is exercised only by test-adapter injection.
- **Alternatives**: Sandbox connecting to the provider DB (rejected: new production grant, FR-042); version-string gating (rejected by FR-024).

## R7 Token revocation
- **Decision**: worker always attempts `POST /api/v1/auth/token/revoke {"accessToken": ...}` on completion, failure, stop or SIGTERM; 200 plus exact JSON acknowledgment `message == "Successfully revoked access token"` → derived access `revoked`; anything else, a killed worker, or no attempt → `cleanup_unknown` with next action "token expires at <expiresAt>; revoke the identity's tokens in the provider console if earlier invalidation is needed".
- **Evidence**: endpoint/body/acknowledgment VERIFIED in v0.166.5 `identity-access-token-router.ts:40-65`, mounted under `/auth` in `v1/index.ts:105-124`. Live revocation remains **UNPROVEN-LIVE**; outcome is never reported as success without a 200 and the exact acknowledgment. See the source links in provider-infisical-v4.md.

## R8 Source continuity without value-derived material (N1)
- **Decision**: `SourceContinuity = (alias, dev, ino, size, mtime_ns, ctime_ns, nlink, uid, mode, names_sha256)` where `names_sha256` hashes the sorted entry **names** (non-secret). Captured from `fstat` on the same descriptor before and after the bounded read; unequal → `source_changed`. A value-only edit with restored mtime still advances `ctime_ns` (utimensat updates ctime). **Unreliable** (→ `continuity_unreliable`, fresh approval required): nlink≠1, foreign uid, mode&0o077, `ctime_ns > now_ns + 5s`, or both `mtime_ns` and `ctime_ns` multiples of 1e9 (coarse-timestamp filesystem). Not claimed: detection of a same-UID actor who can rewrite ctime (needs clock/root control).
- **Rationale**: SourceRegistry `_signature` already uses dev/ino/size/mtime_ns/ctime_ns (sources.py L254, VERIFIED). No `opaque_revision` / `r1_` token on these paths (FR-036); enforced by an AST import guard test.

## R9 Value transport to the worker
- **Decision**: values travel parent → worker only as binary frames on the worker's **stdin pipe**; readback comparison happens in the worker against the frame it received, and the worker returns only a classification. Destination values for scoped runs return over the stdout pipe as `V` frames (as the existing broker does). Bootstrap secret is read by the worker from the OS store via `locator_for_ownership`; the access token never leaves worker memory. Spawn exactly like `BoundedProviderBroker._call`: `[sys.executable, "-I", "-c", ...]`, minimal env, `start_new_session=True`, `close_fds=True`, `stderr=DEVNULL`, `terminate_process_group` on every exit.
- **Alternatives**: AF_UNIX socket or exporter process (rejected by brief and FR-053: no socket-path setup); temp files (FR-021).

## R10 Journal durability and single-controller ownership
- **Decision**: JSONL journal per (profile, destination digest) with `fcntl.flock(LOCK_EX|LOCK_NB)` on a sibling lock file; each record `write` + `os.fsync(file)` + `os.fsync(dir)` before the next step; `attempted` is durable before the POST bytes are sent (worker waits for a `GO` frame). Header carries `controller_id`; a different local controller id, or no local journal while the destination shows a `sandbox-ownership` comment, refuses naming the owner. Journals are never copied/moved to resume.

## R11 Human-only approval
- **Decision**: `sb secrets ownership approve` requires stdin+stdout TTY and foreground process group (same gate pattern as `reveal`, commands/secrets.py L230-295), refuses when `SANDBOX_MCP`/MCP surface or non-interactive; displays the binding summary and requires typing `approve <profile> <approval-short-id>`. Lifetime `--minutes` 1..60 (default 60); effective expiry = min(approval, evidence expiry, access token expiry observed at login). Persisted record contains no credential.

## R12 Scoped run origins
- **Decision**: `origin: source` reads via the existing registered source (file through `SourceRegistry.read`; infisical source through the existing read-only broker with its now-extended `a1-` digest). `origin: destination` reads via the ownership worker `read` action using the profile's **read** client id and `o1-…read` digest (no write grant, FR-046). One run = one ownership domain; mixed origins inside it allowed (FR-044/FR-045). Injection through `runner.run_with_secrets`.
