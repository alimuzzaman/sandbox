# Authenticated credential consumption v1

Status: implementation contract, pending independent review. Source acceptance is not installed authority.

## Accepted installation port

Late import only from `sandbox.installation.binding`: `read_installation_binding(*, home: str|Path|None=None)->dict` and `validate_current(binding: Mapping, *, home=None)->dict`. Both raise InstallationBindingError(code); reads never initialize. Compare the FULL binding, not a subset. Schema 1 fields: installation_id and incarnation are 32 lowercase hex; machine_identity, ownership_marker and runtime_revision are 24 hex; policy_revision is bounded nonempty string; policy_digest is 64 hex; execution_capabilities is mapping[str,int] with positive versions; layout_kind is owner|managed. Missing yields installation_binding_uninitialized. Lifecycle creates IDs for both layouts. GET /hosting/installation belongs exclusively to layout owner under ControlGate. Add no inferred IDs or owner-context fallback. The accepted broad owner policy keeps current approved sudo authority. No 086 capability until real handler integration. An old host_memory_status response proves only its own validated marker/revision/target_identity, never installation ID or credential capability.

## Authentication and nonserializable authority

ControlGate creates frozen AuthenticatedControlReceipt through a module-private issuer after actual successful admission. Middleware attaches it to request.state; do not accept headers/body actor, login, receipt or grant fields. Tailnet receipt records via=tailnet, verified login and node, and server policy epoch; token receipt records via=token and a stable configured service-principal ID, with human identity absent. Never persist the bearer or derive a principal from token content. Revalidate current member policy/installation policy at consume and before effects. Equal admitted operators have full owner rights, while individual actor/request grants remain distinct.

Only CredentialAdmissionService.commit(receipt, resolved_intent, successful_preflight) can create CommittedCredentialReceipt after a durable transaction. An internal constructor seal plus retained row validation prevents dictionary/dataclass construction from becoming authority. `admit_operation` accepts the exact in-process committed receipt and rechecks the retained admission/installation; it does not accept serialized evidence. Private classes are an accidental misuse boundary, not isolation from malicious same-process privileged code. On restart the worker obtains a fresh server-only receipt by validating retained admission, original authenticated provenance, current policy and worker identity; no wire receipt is redeemable. Sibling OwnerJobOperation, delivery.validate_durable_context and ordinary job identity remain separate evidence.

Existing `host stack up` and supported hosting apply consumers dispatch through fixed `sandbox.transports.hosting_credentials`, never SSH to the same host. `host validate` stays static; `host secrets` negotiates admitted names/status inventory. Retained lookup/cancel use the original operation ID when known. Lost-first-response recovery uses the request-key lookup below without requiring an operation ID. Add parser options for explicit original request identity and linked known-refusal retry only where no existing option supplies them; document final spelling with implementation.

Register POST /hosting/credentials/operations, GET /hosting/credentials/operations/{operation_id}, POST /hosting/credentials/lookup, POST .../{operation_id}/cancel and POST /hosting/credentials/inventory behind the existing gate. Installation discovery advertises hosting.credentials=1 only when composition verifies every required service. Route registration and capability registration use explicit manifests. No client-side enablement switch.

POST operation exact schema_version=1 object: request_id, action enum stack_up|host_apply, registered project_ref, complete expected_installation, target_ref including copy/incarnation, source_commit, artifact_digest, immutable nonsecret manifest_digest and selected environment, source_ref+source_revision, profile_ref+profile_revision, ordered mappings, generate_requested, requested_deadline and optional retry_of. The server resolves references independently against registries and compares the complete expected binding. Client declarations are intent requests only. Reject unknown fields, inline provider values, absolute source paths, URLs/argv and duplicate JSON keys. Body <=64KiB, IDs <=128 UTF-8 bytes, mappings <=128, no NaN/Infinity; requested deadline positive, capped to existing finite operation policy. Admission records actual effective deadline. Artifact digest is sha256 of exact registered artifact bytes and committed source identity; dirty/uncommitted source is refused. Artifact metadata resolution must be read-only, not effectful staging.

Each mapping is kind=provider|generated, source_key, destination, consumer_id, consumer_revision and purpose. Resolve destinations as typed inprocess provider slot or app-channel slot bound to exact measured artifact, service/container target and operation, never merely a destination string. Source/profile revisions are opaque registered revisions, not value-derived public fingerprints. Never hardcode supplied PRD revisions as perpetual grants. Inventory returns only declared key name and present|missing|unavailable; do not call a metadata mode that exposes lengths/fingerprints.

Response schema_version=1 has bounded status, request_id, operation_id when durably known, safe code, allowed names/status and availability. Durable accepted response uses 202; identical replay/inspection 200; changed intent 409; gate denial 401; malformed 400; unsupported 503. No child output, exception text, provider body, value-derived metadata, source file paths or serialized grants. Lost/malformed response means acceptance_unknown with original identity retained. Client performs read-only lookup before idempotent replay; no new identity on uncertainty.

Read-only POST `/hosting/credentials/lookup` accepts exactly schema_version=1, installation_id, incarnation, project_ref and request_id. The principal is derived exclusively from the current ControlGate receipt. Resolve retained scope before current mutable source/profile metadata; return known retained status, not_found, or lookup_unknown. No admission or reference refresh follows lookup. POST operation replay finds the original scoped row first and compares submitted canonical intent; new reservations resolve requested references before creation. A source disappearing cannot hide an existing refusal.

## Ledger and effect ordering

Add versioned credential-operation tables via JobRepository APIs, not direct client SQL. Unique key is installation_id/incarnation + authenticated principal + project_identity + request_id. Also retain the full canonical intent and digest. Lookup/reservation compares exact canonical intent in one transaction; caller action cannot choose a new actor partition. Server reference resolution uses pinned requested identities first; an existing frozen refusal remains inspectable even if a source later disappears. Linked retry requires known terminal no-effect refusal and explicit new request identity.

States: reserved -> preflight_refused OR admitted -> running -> succeeded|failed|cancelled|expired|effects_unknown. Admission is a durable server record, not a status field supplied by a client. Reservation confers zero effects. Unknown persistence permits no grant or effect. Preflight refusal is frozen and carries only safe missing/unavailable names and no_effects=true. Compare-and-swap admission against reservation and preflight binding; source/policy drift refuses. Tombstones preserve uniqueness after ordinary outcome retention; pruning must never reopen identity. Reuse existing job persistence locks, finite deadline, cancellation and bounded public projections rather than a second scheduler.

At an effect boundary atomically claim effect_step+fencing_token against running state, unexpired deadline and uncancelled operation, then hold the server-local target mutation transaction during invocation. Use `RecoveryRepository.target_mutation_port("shared_credentials").target_mutation_transaction(canonical_target_key)` through a narrow local adapter registered in the existing target-mutation capability manifest. Hold the target-wide effect lock across the whole effect, including distinct operations of one owner. Lock order is target mutation transaction, short credential-row CAS/cancel transaction, release DB transaction, effect, short completion transaction, release target. Never hold the global jobs DB transaction during provider calls. Source publication separately requires its real source-writer authority. The SSH host-apply lease is not this port. Concurrent duplicate requests never acquire a second claim. Record completion before next step. Unknown effect completion freezes the step and requires supported recovery inspection under the same identity; no blind retry or fabricated rollback. Cancellation serializes against step admission and blocks later steps, while an already-started effect may have unknown outcome. No global lock around provider calls; independent operation/target fences preserve concurrency.

## Broker and intended consumers

`RegisteredCredentialBroker.preflight(intent)` checks exact registered source/profile revisions and all required provider names through the existing secret service. `issue(committed_receipt, intent)` returns only an in-process grant. `consume(grant, consumer_id, effect_step)` rechecks the retained operation, actor/policy, full installation, source/profile revisions, destination, measured artifact, cancellation/deadline and target fence. It selects a fixed trusted consumer in the manifest and invokes it internally. Caller-supplied callbacks never enter from wire. No public resolve/get-value method. Borrowed buffers and sessions are closed in finally; Python cannot promise physical zeroization of immutable provider-library strings.

Provider consumers construct existing fixed Cloudflare/registered provider clients with explicit credentials within the callback; they accept typed nonsecret actions and bound endpoints only. Disable ambient environment/local secret fallback on this path. Do not pass arbitrary upstream URLs, commands, response bodies or headers to the client. Audit safe outcome codes outside secret exception frames; suppress traces/HTTP debug and arbitrary stdout/stderr. Generic SecretService.use_profile and refuse_escalation keep their existing behavior; full owner/sudo operations use the hosting dispatcher and existing owner executor, not an escalation bypass in generic secret-run.

Application consumers use registered broker delivery of a minimal explicit environment or standard protected runtime-secret facility to the reviewed intended server application. Hub getenv compatibility does not require a new application socket protocol or Hub repository edits. Values never reach the invoking laptop, controller responses, ordinary job payloads/logs/polls, public artifacts, source/image layers, or arbitrary staging/config/temp files. Intended-recipient environment/container configuration is within the reviewed recipient boundary, not a public output. Never inherit the owner's ambient environment.

Persistent material is permitted only in an explicitly approved server credential/runtime-secret facility. The consumer profile must name its fixed installation-owned location, owner-only permissions, allowed readers, atomic creation, bounded retention and cleanup, and backup/export exclusions. Existing environment.env or chmod0600 alone does not establish approval. Implement and review that facility and the real launcher against registered target/artifact mappings; report any exact unresolved storage/export risk for human release review. Broker resolves and delivers entirely on the same bound server after committed admission and under current target authority. No provider value enters a source export or client transport. Known Hub mappings are compatibility examples only; exact GS artifact/SHA/mappings remain unverified. Unsupported consumers refuse before effects.

Generated-runtime credentials remain a distinct kind and separate generation authority, after successful provider preflight/admission. Retain existing authorized generated-runtime delivery, but never route a required provider key through it. Missing provider keys refuse even with generate_requested=true.
